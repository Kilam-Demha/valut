
# 🧠 Data Structures — Lesson 01

## شنو هي Data Structure؟

### 1. التعريف

**Data Structure = طريقة لتنظيم وتخزين البيانات فـ الذاكرة (Memory)، باش نقدروا نوصلو ليها ونعالجوها بكفاءة.**

بمعنى بسيط:

> **Data = المعلومات**  
> **Structure = الطريقة اللي نظمنا بها هاد المعلومات**

مثلاً عندنا:

```
10   20   30   40   50
```

هاد الأرقام هي **Data**.

أما الطريقة اللي غادي نخزنو وننظمو بها هاد الأرقام فهي **Data Structure**.

---

# 2. علاش محتاجين Data Structures؟

حيت ماشي غير مهم **شنو عندنا من Data**، ولكن مهم كذلك:

```
كيفاش نخزنها؟
كيفاش نوصل ليها؟
كيفاش نزيد Data؟
كيفاش نحيد Data؟
كيفاش نقلب على Data؟
كيفاش نرتب Data؟
وشحال غادي تكلفنا هاد العمليات؟
```

مثلاً عندك مليون عنصر.

واش أحسن نخزنهم فـ:

```
Array
```

ولا:

```
Linked List
```

ولا:

```
Tree
```

الجواب كيعتمد على **شنو باغي تدير بالبيانات**.

---

# 3. الهدف الحقيقي ديال Data Structures

الهدف هو:

```
Organize Data
     ↓
Efficient Operations
     ↓
Better Performance
```

يعني كنحاولو نخليو العمليات:

- أسرع
- أقل استهلاكاً للـMemory
- مناسبة للمشكل

---

تخيل عندك مكتبة فيها:

```
100,000 كتاب
```

إلا حطيتي الكتب عشوائياً، غادي يكون صعيب تلقى كتاب.

ولكن إلا نظمتيهم حسب:

```
Category
   ↓

```

غادي تولي عملية البحث أسهل.

هاد التنظيم هو الفكرة الأساسية وراء **Data Structures**.

هاد الفرق مهم جداً.

> **كيفاش نخزن وننظم البيانات؟**

```
Array
Linked List

Queue
Tree
Graph
```

### Algorithm

# 7. التصنيف الكبير

Data Structures كنقسموهم بشكل عام إلى:

```
                 DATA STRUCTURES

             ┌─────────┴─────────┐
             │                   │

```

# 🧠 PRO NOTE — حفظ هادي

```
DATA STRUCTURE
│
├── تنظيم وتخزين البيانات
│
├── تسهيل الوصول للبيانات
│
├── تسهيل العمليات على البيانات
│
└── تحسين الكفاءة
        │
        ├── Time Complexity
        └── Space Complexity
```

### 🔑 الخلاصة

> **Data Structure هي طريقة منظمة لتخزين البيانات والتعامل معها بكفاءة، والاختيار ديالها كيعتمد على العمليات اللي بغينا نديرو على هاد البيانات.**



## 1. شنو هي Time Complexity؟

**Time Complexity = كيفاش كيكبر الوقت/عدد العمليات ديال Algorithm ملي كيكبر حجم الـ input.**

مهم: ما كنقيسوش **الثواني الحقيقية**، ولكن كنقيسو **عدد العمليات تقريباً**.

مثلاً عندنا:

```
printf("Hello");
```

هاد العملية كتوقع مرة وحدة، سواء كان عندك input صغير ولا كبير.

إذن:

**Time Complexity = O(1)**

---

## 2. شنو هو `n`؟

`n` كتمثل **حجم الـ input**.

مثلاً عندنا array:

```
int tab[5] = {10, 20, 30, 40, 50};
```

هنا:

```
n = 5
```

إلا كان عندنا:

```
[10, 20, 30, 40, 50, 60, 70, 80]
```

فـ:

```
n = 8
```

يعني `n` كتقول لينا **شحال من عنصر خاصنا نعالجو**.

---

# 3. أول Complexity: O(1)

مثال:

```
int x = tab[3];
```

حتى إلا كان عندك:

```
n = 10
n = 100
n = 1,000,000
```

الوصول لـ `tab[3]` كيبقى عملية وحدة تقريباً.

إذن:

```
O(1)
```

**Constant Time**

---

# 4. O(n)

شوف:

```
for (int i = 0; i < n; i++)
{
    printf("%d\n", tab[i]);
}
```

إلا:

```
n = 5
```

الـ loop كتدور 5 مرات.

إلا:

```
n = 100
```

كتدور 100 مرة.

إلا:

```
n = 1,000
```

كتدور 1000 مرة.

إذن عدد العمليات كيكبر مع `n`.

```
O(n)
```

**Linear Time**

---

# 5. O(n²)

دابا:

```
for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        printf("%d %d\n", i, j);
    }
}
```

عندنا loop داخل loop.

إلا:

```
n = 5
```

الأولى = 5 مرات  
الثانية = 5 مرات لكل دورة

إذن:

```
5 × 5 = 25
```

إلا:

```
n = 100
```

```
100 × 100 = 10,000
```

إذن:

```
O(n²)
```

**Quadratic Time**

---

## القاعدة المهمة دابا

حفظ هاد الثلاثة مزيان:

```
O(1)   → العملية ما كتزادش مع n

O(n)   → العملية كتزاد بنفس سرعة n

O(n²)  → جوج loops داخل بعضياتهم غالباً
```

### مثال سريع:

```
n = 10

O(1)  → تقريباً 1
O(n)  → تقريباً 10
O(n²) → تقريباً 100
```


مزيان، نكملو دابا من بعد `O(n²)`.

# 6. O(log n)

هاد النوع مهم بزاف، خصوصاً فـ **Searching**.

الفكرة الأساسية:

> كل خطوة كتـنقص الـ problem تقريباً للنصف.

مثال عندك:

```
[1 2 3 4 5 6 7 8]
```

بغيتي تلقى `7`.

ماشي ضروري تقلب على العناصر كاملين. كتقدر تشوف الوسط:

```
[1 2 3 4] | [5 6 7 8]
              ↑
```

ومن بعد كتستبعد النصف اللي ما فيهش الجواب.

كل مرة:

```
n
↓
n/2
↓
n/4
↓
n/8
↓
...
```

لهذا كنقولو:

```
O(log n)
```

### مثال

إلا كان عندك:

```
n = 16
```

عدد المرات باش نوصلو لـ `1`:

```
16 → 8 → 4 → 2 → 1
```

يعني تقريباً:

```
log₂(16) = 4
```

---

# 7. O(n log n)

هاد واحد كيجمع بين:

```
O(n)
```

و:

```
O(log n)
```

يعني تقريباً:

```
n × log n
```

كيبان بزاف فـ **efficient sorting algorithms** بحال Merge Sort.

مثلاً:

```
n = 1000

n log₂(n)
≈ 1000 × 10
≈ 10,000
```

بينما:

```
n² = 1,000,000
```

لهذا `O(n log n)` أحسن بزاف من `O(n²)` ملي `n` كتكون كبيرة.

---

# 8. O(2ⁿ)

هنا الأمور كتولي ثقيلة بزاف.

مثلاً:

```
n = 5
2⁵ = 32

n = 10
2¹⁰ = 1024

n = 20
2²⁰ = 1,048,576
```

يعني كلما زدنا `n`، عدد العمليات كيطلع بسرعة كبيرة.

كتلقاه غالباً فبعض **recursive algorithms** والمشاكل اللي فيها تجربة بزاف ديال الاحتمالات.

---

# الترتيب اللي خاصك تحفظ

من الأفضل → للأسوأ، بشكل عام:

```
O(1)
  ↓
O(log n)
  ↓
O(n)
  ↓
O(n log n)
  ↓
O(n²)
  ↓
O(2ⁿ)
  ↓
O(n!)
```

يعني:

```
O(1)       🔥 ممتاز
O(log n)   🔥 ممتاز
O(n)       ✅ مزيان
O(n log n) ✅ مزيان
O(n²)      ⚠️ كيقدر يكون ثقيل
O(2ⁿ)      ❌ ثقيل بزاف
O(n!)      💀 ثقيل جداً
```

## PRO NOTE

```
TIME COMPLEXITY

O(1)       → ثابت
O(log n)   → كنقسم problem
               تقريباً للنصف

O(n)       → كنمر على العناصر
               واحد بواحد

O(n log n) → n × log n

O(n²)      → غالباً loop داخل loop

O(2ⁿ)      → exponential

O(n!)      → factorial
```

**دابا أهم خطوة:** قبل ما ندوزو لـ Space Complexity، خاصك تتعلم **كيفاش نستخرج Time Complexity من كود C**. هادي هي المهارة الحقيقية.

# 1. شنو هي Space Complexity؟

**Space Complexity = شحال من Memory إضافية كيحتاج Algorithm باش يخدم، مقارنةً مع حجم الـ input `n`.**

يعني:

```
Time Complexity  → شحال من operations؟
Space Complexity → شحال من memory؟
```

---

# 2. مثال بسيط

```
int x;
```

عندنا variable وحدة.

الـ memory ديالها ما كتزادش مع `n`.

إذن:

```
Space Complexity = O(1)
```

---

# 3. Array بحجم `n`

شوف:

```
int tab[n];
```

إلا كان:

```
n = 10
```

عندنا 10 عناصر.

إلا:

```
n = 1000
```

عندنا 1000 عنصر.

إذن الـ memory كتزاد مع `n`:

```
Space Complexity = O(n)
```

---

# 4. الفرق بين Time و Space

مثلاً:

```
for (int i = 0; i < n; i++)
{
    printf("%d\n", i);
}
```

ما عندناش array جديدة ولا memory كتزاد مع `n`.

ولكن loop كتدور `n` مرات.

إذن:

```
Time  → O(n)
Space → O(1)
```

هاد المثال مهم جداً.

**Time و Space ماشي نفس الحاجة.**

---

# 5. مثال آخر

```
int tab[n];

for (int i = 0; i < n; i++)
{
    printf("%d\n", tab[i]);
}
```

هنا:

```
Time  → O(n)
Space → O(n)
```

علاش؟

- loop → `n` operations
- array → `n` elements فـ memory

---

# 6. O(n²) فـ Space

مثلاً:

```
int matrix[n][n];
```

عندنا:

```
n × n
```

يعني:

```
n²
```

إذن:

```
Space Complexity = O(n²)
```

مثلاً:

```
n = 3

3 × 3 = 9
```

و:

```
n = 100

100 × 100 = 10,000
```

---

# 7. مهم: Auxiliary Space

كاين واحد المصطلح مهم:

**Auxiliary Space**

هو الـ **memory الإضافية** اللي كيستعملها الـ algorithm، ماشي بالضرورة الـ input نفسه.

مثلاً:

```
void printArray(int tab[], int n)
{
    int i;

    for (i = 0; i < n; i++)
        printf("%d\n", tab[i]);
}
```

الـ `tab` راه input موجود أصلاً.

ولكن variables بحال:

```
i
```

ما كتكبرش مع `n`.

إذن الـ auxiliary space:

```
O(1)
```

---

# PRO NOTE

```
SPACE COMPLEXITY

O(1)
→ Memory ثابتة

O(n)
→ Memory كتزاد مع n

O(n²)
→ Memory كتزاد مع n²
```

والفرق الأساسي:

```
TIME
→ عدد العمليات

SPACE
→ Memory المستعملة
```

### مثال تحفظو:

```
int tab[n];

for (int i = 0; i < n; i++)
{
    printf("%d\n", tab[i]);
}
```

```
Time  = O(n)
Space = O(n)
```

ولكن:

```
for (int i = 0; i < n; i++)
{
    printf("%d\n", i);
}
```

```
Time  = O(n)
Space = O(1)
```

**الخطوة الجاية المهمة:** نتعلمو كيفاش نحسبو **Time + Space Complexity مباشرة من كود C**، حيث هنا غادي تبدأ Complexity تولي عملية ماشي غير نظرية.




# شنو هو Dominant Term؟

**Dominant Term = الحد اللي كيكبر بأسرع شكل ملي `n` كتزاد.**

فـ Time Complexity، إلا كان عندنا بزاف ديال العمليات، كنشوفو **شنو هو الجزء اللي غادي يولي هو المسيطر ملي `n` تكبر بزاف**.

---

### مثال 1

عندنا:

```
O(n) + O(n²)
```

نجربو `n = 10`:

```
n   = 10
n²  = 100
```

`n²` أكبر.

إلا `n = 1000`:

```
n   = 1,000
n²  = 1,000,000
```

الفرق ولى كبير بزاف.

إذن:

```
O(n) + O(n²)
       ↑
  Dominant Term
```

والنتيجة:

```
O(n²)
```

---

### مثال 2

```
O(n) + O(log n)
```

إلا `n` كتكبر:

```
n       → كتكبر بسرعة
log(n)  → كتكبر ببطء
```

إذن:

```
O(n) + O(log n)
        ↓
      O(n)
```

`O(n)` هي **Dominant Term**.

---

### مثال 3

```
O(n²) + O(n³)
```

`n = 10`:

```
n² = 100
n³ = 1000
```

إذن `n³` أكبر.

```
O(n²) + O(n³)
        ↓
      O(n³)
```

---

## القاعدة الذهبية 🧠

إلا كانو عندك terms مجموعين:

```
O(...)
```

خلي **اللي كيكبر أسرع**.

الترتيب اللي خاصك تعرف:

```
O(1)
  ↓
O(log n)
  ↓
O(n)
  ↓
O(n log n)
  ↓
O(n²)
  ↓
O(n³)
  ↓
O(2ⁿ)
  ↓
O(n!)
```

مثلاً:

```
O(1) + O(n) + O(n²)
             ↑
       Dominant Term

= O(n²)
```

---

## ولكن انتبه ⚠️

**Dominant Term ماشي معناها دائماً نحيدو أي حاجة.**

مثلاً:

```
O(n² + n)
```

هنا `n²` هو dominant:

```
n² + n
 ↓
O(n²)
```

ولكن:

```
O(n × log n)
```

ما عندناش `n` و `log n` مجموعين؛ راه **مضروبين**:

```
n × log n
```

إذن كتبقى:

```
O(n log n)
```

### PRO NOTE

```
الجمع → كنقلبو على Dominant Term

O(n) + O(n²)
       ↓
      O(n²)

الضرب → كنحسبو العلاقة

O(n) × O(log n)
       ↓
   O(n log n)
```

**بمعنى بسيط:**  
`Dominant Term` هو **الحاجة اللي غادي تسيطر على تكلفة الـ algorithm ملي `n` تولي كبيرة بزاف**.

### 🧠 PRO NOTE

```
Algorithm واحد:
O(n) + O(n²)
        ↓
Dominant Term
        ↓
O(n²)

جوج Algorithms:
A → O(n)
B → O(n²)
        ↓
نقارنهم
        ↓
O(n) أفضل للـ n الكبيرة
```

يعني **Dominant Term ماشي هو اللي كيختار Algorithm مباشرة**؛ هو كيساعدك تحدد الـ **Time Complexity النهائية** ديال Algorithm، ومن بعد كتقدر تقارن Algorithms.




# 🥇 Data Structure 01 — Array

## 1. شنو هي Array؟

**Array** هي Data Structure كتخليك تخزن **مجموعة ديال البيانات من نفس النوع** فـ الذاكرة، فـ أماكن متجاورة.

مثلاً:

```
int tab[5];
```

هنا عندنا Array فيها **5 عناصر من نوع `int`**.

نقدروا نمثلوها هكا:

```
Array
┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │ 50 │
└────┴────┴────┴────┴────┘
   0    1    2    3    4
   ↑
 index
```

الأرقام اللي لتحت هما **Index**.

---

## 2. علاش Index كيبدا من 0؟

حيت أول عنصر كاين على **offset = 0** من بداية Array.

يعني:

```
index 0 → أول عنصر
index 1 → ثاني عنصر
index 2 → ثالث عنصر
...
```

مثلاً:

```
int tab[5] = {10, 20, 30, 40, 50};
```

إذن:

```
tab[0] = 10
tab[1] = 20
tab[2] = 30
tab[3] = 40
tab[4] = 50
```

⚠️ آخر Index ماشي `5`.

هو:

```
size - 1
5 - 1 = 4
```

---

## 3. علاش Array مهمة فـ Data Structures؟

حيت العناصر ديالها مخزنين **متتابعين فـ Memory**:

```
RAM

1000 → 10
1004 → 20
1008 → 30
1012 → 40
1016 → 50
```

مثلاً إلا كان `int` حجمو 4 bytes، كل عنصر كيزيد تقريباً 4 bytes.

وهنا كتجي القوة ديال Array:

إلى عرفنا **البداية + index + حجم العنصر**، نقدروا نوصلو مباشرة للعنصر.

ولهذا:

### Access فـ Array = `O(1)` ⚡

مثلاً:

```
tab[3]
```

ما محتاجش يدوز على:

```
10 → 20 → 30 → 40
```

كيحسب المكان مباشرة ويمشي ليه.

---
### 🧠 PRO NOTE

```
ARRAY

• مجموعة عناصر من نفس النوع
• العناصر مخزنين بشكل متتابع فـ Memory
• Index كيبدا من 0
• آخر Index = size - 1
• Access by index = O(1)
```

 دابا ندخلو لواحد النقطة **مهمة بزاف فـ Data Structures**: علاش Array عندها **Access = O(1)**.

## 🧠 كيفاش `tab[4]` كتلقى العنصر؟

نفترضو:

```
int tab[5] = {10, 20, 30, 40, 50};
```

وكل `int` = **4 bytes**.

فـ RAM ممكن تكون هكا:

```
Address

1000  →  10    ← tab[0]
1004  →  20    ← tab[1]
1008  →  30    ← tab[2]
1012  →  40    ← tab[3]
1016  →  50    ← tab[4]
```

لاحظ:

```
1000
1004
1008
1012
1016
```

كل مرة كنزيدو **4 bytes**.

---

## 🔑 القاعدة

الـ CPU يقدر يحسب العنوان ديال أي عنصر مباشرة:

```
Address =
Base Address + (Index × Size of Element)
```

مثلاً `tab[4]`:

```
Base = 1000
Index = 4
Size = 4 bytes

Address = 1000 + (4 × 4)
        = 1016
```

يمشي مباشرة لـ `1016` ويجيب `50`.

ما محتاجش يدوز على العناصر اللي قبل منو.

لهذا:

```
tab[0] → O(1)
tab[2] → O(1)
tab[4] → O(1)
tab[999] → O(1)
```

حتى إلا كانت Array كبيرة، **الوصول بالـ index كيظل O(1)**.

---

### ⚠️ نقطة مهمة

`O(1)` ما معناهاش:

> "ديما كيحتاج نفس عدد الـ bytes."

المعنى هو:

> **عدد الخطوات للوصول للعنصر ما كيكبرش مع `n`.**

---

### 🧠 PRO NOTE

```
ARRAY ACCESS

Address = Base + (Index × Element Size)

مثال:
Base = 1000
Index = 4
Element Size = 4

→ Address = 1016

Therefore:
Access by index = O(1)
```

# 6️⃣ Traversal فـ Array

## شنو هو Traversal؟

**Traversal** يعني:

> ندوزو على **جميع العناصر** ديال الـ Array واحد بواحد، غالباً باش نقراوهم أو نديرو عليهم شي عملية.

مثلاً:

```
int tab[5] = {10, 20, 30, 40, 50};
```

إلى بغينا نطبعو جميع العناصر:

```
for (int i = 0; i < 5; i++)
{
    printf("%d\n", tab[i]);
}
```

البرنامج غادي يدوز:

```
tab[0] → 10
   ↓
tab[1] → 20
   ↓
tab[2] → 30
   ↓
tab[3] → 40
   ↓
tab[4] → 50
```

يعني خاصنا نشوفو **كل عنصر**.

---

## ⏱️ Time Complexity

إلى كان عندنا `n` عناصر:

```
i = 0
i = 1
i = 2
...
i = n-1
```

يعني تقريباً `n` operations.

إذن:

**Traversal = O(n)**

---

## 💾 Space Complexity

إلى كنا غير كنستعملو:

```
int i;
```

وما كنخلقوش Array جديدة، فالـ extra memory ثابتة:

**Space = O(1)**

إذن:

```
Traversal
├── Time  → O(n)
└── Space → O(1)
```

### 🧠 PRO NOTE

```
Access   → O(1)
Search   → O(n)
Traversal → O(n)
```

الفرق:

- **Access** → بغينا عنصر معروف بالـ index.
- **Search** → بغينا نلقاو عنصر وما عارفينش index.
- **Traversal** → بغينا ندوزو على **كاع العناصر**.

---

## 7️⃣ Insert فـ Array

دابا ندوزو لعملية مهمة: **Insert = إضافة عنصر**.

مثلاً:

```
[10][20][30][40][50]
```

وبغينا ندخلو `25` بين `20` و `30`.

المشكل هو أن `30, 40, 50` خاصهم يتحركو:

```
قبل:
[10][20][30][40][50]

من بعد:
[10][20][25][30][40][50]
          ↑
        new
```

يعني خاصنا نحركو العناصر باش نفرغو المكان.


### 🧠 DELETE فـ ARRAY

**Delete** = نحيدو عنصر من Array مع الحفاظ على ترتيب العناصر.

مثال:

```
قبل:
[10][20][30][40][50]

حيدنا 30:

[10][20][40][50]
```

باش العناصر يبقاو **متتابعين**، العناصر اللي من بعد العنصر المحذوف خاصها تدير **Shift Left**:

```
[10][20][30][40][50]
       ❌   ←   ←

[10][20][40][50][ ]
```

### ⏱️ Time Complexity

```
Delete من البداية → O(n)
Delete من الوسط   → O(n)
Delete من النهاية → O(1)
```

**علاش؟**

- البداية: تقريباً جميع العناصر خاصها تتحرك.
- الوسط: العناصر اللي من بعد العنصر خاصها تتحرك.
- النهاية: ما كاين حتى Shift → غير كننقصو `size`.

### ⚠️ مهم فـ C

خاص نفرقو بين:

```
Capacity = الحجم المحجوز فـ Memory
Size     = عدد العناصر اللي كنعتابروهم حالياً داخل Array
```

مثلاً:

```
Capacity = 5
Size     = 4

[10][20][30][40][ ]
```

إلى حذفنا `40`:

```
Size = 3

[10][20][30][ ][ ]
```

الـ **Memory ما نقصاتش بالضرورة**؛ غير الـ **logical size** نقص.

### 🧠 PRO NOTE

> **Delete فـ Array = Remove + Shift Left عند الحاجة + Update Size**

```
Beginning → O(n)
Middle    → O(n)
End       → O(1)
```
🧠 **PRO NOTE:**

```
Array Operations

Access   → O(1)
Update   → O(1)
Search   → O(n)
Traversal→ O(n)

Insert:
  بداية → O(n)
  وسط   → O(n)
  نهاية → O(1)* => c (dynamic allocation memory realoc + poniter)

Delete:
  بداية → O(n)
  وسط   → O(n)
  نهاية → O(1)
```

# 2️⃣ Dynamic Array

Dynamic Array هو Array اللي الذاكرة ديالو كتتحجز **وقت Runtime**، وتقدر تبدل الحجم ديالو باستعمال Dynamic Memory Allocation.

فـ C كنستعملو خصوصاً:

```
malloc()
realloc()
free()
```

مثلاً:

```
int *tab = malloc(5 * sizeof(int));
```

دابا حجزنا Memory لـ 5 `int`:

```
Heap

[ ][ ][ ][ ][ ]
```

ومن بعد إلا احتجنا نكبروه:

```
tab = realloc(tab, 10 * sizeof(int));
```

يقدر يولي عندنا:

```
[ ][ ][ ][ ][ ][ ][ ][ ][ ][ ]
```

يعني:

```
5 elements capacity
        ↓
10 elements capacity
```

⚠️ ولكن `realloc()` **ماشي مضمون يبقى نفس المكان فـ Memory**. يقدر يلقى بلاصة جديدة وينقل البيانات ليها.

---

# 🔥 الفرق الأساسي

||Static Array|Dynamic Array|
|---|---|---|
|الحجم|محدد|قابل للتغيير|
|Allocation|غالباً قبل/أثناء تعريف الـ Array|Runtime|
|تغيير الحجم|❌|✅|
|Dynamic Memory|❌|✅|
|C functions|—|`malloc`, `realloc`, `free`|
|المرونة|قليلة|كبيرة|

## 🧠 حاجة مهمة جداً: Stack vs Heap

غالباً ملي كتكتب:

```
int tab[100];
```

الـ Array المحلي كيكون فـ **Stack**.

أما:

```
int *tab = malloc(100 * sizeof(int));
```

فالـ data اللي تحجزات بـ `malloc` كتكون فـ **Heap**.

يعني:

```
             PROGRAM
                │
        ┌───────┴───────┐
        ↓               ↓
      STACK            HEAP
        │                │
 int tab[100]      malloc(...)
```

وهنا غادي نبداو نفهمو علاش **Pointers** مهمين بزاف فـ Data Structures.

# ⚠️ ملاحظة Pro

**Dynamic Array ماشي هو Linked List.**

بجوجهم يقدرو يكبرو، ولكن الطريقة مختلفة:

```
Dynamic Array:

[10][20][30][40][50]
 ↑──────── contiguous ────────↑


Linked List:

[10] → [20] → [30] → [40]
  ↑      ↑      ↑      ↑
nodes ممكن يكونو فبلايص مختلفة فالـ Memory
```

الـ Dynamic Array كيحافظ على **contiguous memory**، بينما Linked List ما كتحتاجش تكون العناصر ديالها متجاورة.

### 🧠 PRO NOTE

> **Static Array:** الحجم ثابت.  
> **Dynamic Array:** الحجم يمكن يتبدل أثناء Runtime باستعمال Dynamic Memory.  
> **Dynamic Array ≠ Linked List.**

والخطوة المنطقية من هنا هي نفهمو **`malloc()` من الصفر**، حيث هي الأساس باش تفهم Dynamic Array فـ C.
